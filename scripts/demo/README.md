# デモスクール（営業デモ・動作確認用）

NLTCとは別の「t-logデモスクール」（slug: `demo` / plan: `demo`）を作り、ダミーの選手・コーチ・保護者・
管理者アカウントと、約2か月分のダミーデータを入れるスクリプトです。実在の個人情報は使っていません。
NLTCを含む他のスクールのデータには書き込みません（すべての書き込み・削除はデモスクールの `school_id` に限定）。

## 使い方

```bash
# 作成（引数なしはドライラン：接続先と作成内容を表示するだけで、何も書き込まない）
npm run demo:seed
npm run demo:seed -- --yes

# 件数と、他校との隔離（RLS）の確認
# 使い捨ての別スクール（slug: demo-verify-other）と確認用コーチを一時的に作り、確認後にスクールごと削除する
# （NLTCには一切書き込まない）
npm run demo:verify

# 削除（引数なしはドライラン）
npm run demo:cleanup
npm run demo:cleanup -- --yes
```

- 接続情報は `.env.local`（`NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_ANON_KEY` / `SUPABASE_SERVICE_ROLE_KEY`）から読みます。
- ログイン情報（パスワード）は画面に出さず、ホームフォルダの `t-log-demo-credentials.txt` に保存します
  （リポジトリには置かないこと）。再実行時は同じパスワードを使い続けます。
- 日付はすべて実行日（日本時間）基準です。コーチ画面のアラートは「今日の」Daily Logで判定されるため、
  **デモの前日〜当日に `npm run demo:seed -- --yes` を再実行**すると、日付が最新の状態に作り直されます
  （アカウントは再利用し、デモスクール内の記録データだけを作り直します）。
- 月次レポートの評価文は固定文で、今月分の下書きは「今月に大会・痛みの記録がある」前提の文面です。
  月の前半（おおむね13日以前）に実行すると、記録の日付が先月側にずれて文面と合わないことがあります。

## 作成される内容

| 種類 | 内容 |
|---|---|
| アカウント | デモ 管理者（school_admin）/ デモ コーチ / デモ 太郎（中2・U14）/ デモ 花子（小6・U12）/ デモ 保護者（太郎と紐付け） |
| daily_logs | 両選手の先月1日〜今日（先月分レポートに丸1か月分が入るように）。太郎は今日「疲労8・肘の痛み」（RED）、花子は今日未入力 |
| match_logs | 太郎6件・花子5件（大会名・対戦相手はすべて架空） |
| goal_logs / coach_notes | 今月・先月の目標 / internal と shared_with_family のメモ |
| physical_measurements / tournament_schedules | 各選手2件ずつ |
| monthly_reports | 先月分＝公開済み、今月分＝下書き（評価文は固定文。AIは呼ばない。PDFは作らない） |

## 注意

- 毎月1日の自動レポート生成（`app/api/cron/generate-monthly-reports`）は全スクールの在籍選手が対象のため、
  デモスクールの選手にも下書きが作られ、AIの文章生成が走ることがあります（評価文が既に入っている下書きは対象外）。
- デモ画面でコーチがレポートの「生成」操作をした場合も、AIが呼ばれます。
